## 1. Идея и модель

Двусторонний маркетплейс услуг для Одессы: заказчик ищет мастера по ремонту/
стройке (сантехник, электрик, отделочник, плиточник, мастер на час, мебельщик),
мастер ищет заказы. Ниша: ремонт/стройка (не общий OLX/Kabanchik).

Монетизация (план, ещё не реализована технически):
- Заказчики: бесплатно с лимитами → подписка Premium 100–200 грн/мес (без рекламы, безлимит).
- Мастера: 7 дней триал → платные тарифы Bronze/Silver/Gold ($5–20/мес).
- Комиссия с оплаты: 3–5% без подписки, 1–1.5% с подпиской.
- На старте (MVP) — **без встроенных платежей**, оплата вручную (перевод на карту),
  активация подписки вручную через Supabase. Автоплатежи (LiqPay/Fondy + Supabase
  Edge Functions) — только после 30+ мастеров.

## 2. Технический стек

- **Фронтенд:** статические HTML/CSS/JS, без фреймворков.
- **Хостинг фронтенда:** GitHub Pages, репозиторий `lphabardo/RemGo`,
  сайт: `https://lphabardo.github.io/RemGo/`.
- **Бэкенд/БД:** Supabase (Postgres + REST API), клиент подключается через
  `@supabase/supabase-js@2` с CDN (jsdelivr), анонимный ключ зашит в `app.js`
  (это нормально при включённых RLS-политиках — они включены).
- **Формат:** PWA — есть `manifest.json` и `sw.js` (service worker, кэш офлайн).
- Supabase Project: `RemGo`, Project ID: `nnltklrgemdoldwnlehg`.

## 3. Схема базы данных (Supabase, таблицы)

- **categories** — id, name, slug, icon, display_order. 6 категорий:
  сантехники, электрики, отделочники и маляры, плиточники, мастера на час, мебельщики.
- **districts** — id, name, slug, is_active, display_order. Районы Одессы
  (Малиновский, Фонтанка, Суворовский, Пересыпский, Черноморск (неактивен),
  Приморский, Таирово, Киевский).
- **profiles** (мастера) — id, name, phone, telegram_username, category_id,
  district_id, city, photo_url, gallery (jsonb), price_from, price_currency,
  description, rating, review_count, is_verified, is_active, subscription_status,
  subscription_expires_at, trial_used, created_at, updated_at. Сейчас ~6 тестовых
  профилей.
- **orders** (заявки от клиентов) — id, customer_name, customer_phone,
  description, category_id, district_id, address. Таблица создана, но форма
  заявки от клиента (не мастера) ещё не подключена/не используется активно.
- **reviews** — id, profile_id, author_name, text, rating, is_approved, created_at.
  Таблица создана, пустая, функционал отзывов ещё не реализован во фронтенде.

## 4. Файлы проекта и что они делают

- `index.html` — главная: категории, фильтры (категория/район), список мастеров,
  баннер доставки стройматериалов, подключает `app.js`, регистрирует `sw.js`.
- `app.js` — вся логика: загрузка categories/districts/profiles из Supabase,
  рендер карточек, фильтрация, клик по карточке мастера → переход на `master.html?id=`.
  **Важно:** переход на клик по карточке сделан через `initGridClicks()` —
  делегирование событий на `.master-card` (а не inline onclick), потому что
  inline-обработчик конфликтовал со ссылками (Позвонить/Telegram) на десктопе.
  Это уже исправлено в текущей версии файла.
- `styles.css` — все стили, дизайн-токены в `:root` (оранжевый #E85D04,
  графит #2B2D42 и т.д.).
- `register.html` — форма регистрации мастера (пишет в Supabase `profiles`).
- `master.html` — страница профиля отдельного мастера (аватар, галерея, инфо).
- `manifest.json`, `sw.js`, `icon.svg`, `icon.png` — PWA-обвязка.
